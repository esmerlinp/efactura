Documentación de la API

Autenticación

Todas las peticiones de esta API requieren la API Key de tu empresa. Puedes enviarla como X-API-Key o como Authorization: Bearer <API-Key>. Para pruebas usa X-Sandbox-Mode: true; para producción X-Sandbox-Mode: false. El acceso productivo requiere completar previamente el acuerdo contractual.

X-API-Key: ef_xxxxxxxxxxxxxxxx
X-Sandbox-Mode: true   # true = sandbox, false = producción
Content-Type: application/json

Bases oficiales: sandbox https://sandbox.one.vykcore.com y producción https://one.vykcore.com. Los endpoints de la API agregan el prefijo /api/v1, por ejemplo https://sandbox.one.vykcore.com/api/v1/invoices/emit. Una solicitud productiva sin acuerdo devuelve 403 PRODUCTION_AGREEMENT_REQUIRED.

POST/invoices/emit

Emite un comprobante fiscal electrónico. Calcula impuestos (ITBIS, ISC y retenciones), consume una secuencia autorizada, firma el XML y lo envía directamente a la DGII. La API puede responder con estado pendiente; consulta luego el estado del documento.

Cabecera opcional

Idempotency-KeyEvita emisiones duplicadas para una misma clave.

Cuerpo (principales campos)

itemsrequeridoArray con al menos un artículo. Campos principales: name, price, quantity, itbis_rate, type y unit.
client_rncRNC/Cédula del cliente.
client_nameRazón social del cliente.
ecf_typeTipo de comprobante. Usa el nombre configurado o el código: E31, E32, E33, E34, E41, E43, E44, E45, E46 o E47. Por defecto: E32.
payment_methodEfectivo, Cheque / Transferencia, Tarjeta…
due_dateFecha de vencimiento (YYYY-MM-DD).
discount_rateDescuento global (0.0–1.0).
retained_isr_rate / retained_itbis_rateTasas de retención como decimal, por ejemplo 0.10.
idempotency_keyTambién se acepta en el cuerpo, aunque se recomienda usar la cabecera Idempotency-Key.
income_typeTipo de ingreso DGII (ej. 01 - Ingresos por operaciones).
 
curl -X POST {{ base_url }}/invoices/emit \
  -H "Content-Type: application/json" \
  -H "X-API-Key: TU_API_KEY" \
  -d '{
    "client_rnc": "131880681",
    "client_name": "CLIENTE DE EJEMPLO",
    "ecf_type": "E32",
    "items": [
      {"name": "Servicio de consultoría", "price": 1000.00, "quantity": 1, "itbis_rate": 0.18}
    ]
  }'

Respuesta exitosa: success, invoice_id, encf, track_id, xmlSignature, qrCodeURL, pdfUrl, xmlUrl y total. En caso de rechazo se devuelve HTTP 422 con details.

Reglas fiscales

E31 requiere identificar al comprador con RNC o cédula. E32 puede usar consumidor final; para comprobantes de consumo menores de RD$250,000 puede aplicar el flujo RFCE de la DGII. Las notas E33/E34 requieren la referencia del comprobante original. Usa GET /metadata/catalogs para consultar valores de referencia.

POST/invoices/calculate

Calcula los totales fiscales exactos (subtotal, ITBIS, ISC, retenciones) sin emitir el comprobante.

curl -X POST {{ base_url }}/invoices/calculate \
  -H "Content-Type: application/json" \
  -H "X-API-Key: TU_API_KEY" \
  -d '{"items": [{"price": 1000, "quantity": 2, "itbisRate": 0.18}]}'

GET/invoices/{invoice_id}/status

Consulta el estado, eNCF, Track ID y sincronización con la DGII de un comprobante. El identificador de la ruta es el invoice_id interno devuelto por la emisión, no el Track ID.

curl {{ base_url }}/invoices/ID_DEL_DOCUMENTO/status \
  -H "X-API-Key: TU_API_KEY"

POST/invoices/{invoice_id}/cancel

Anula un e-CF emitido enviando la solicitud de anulación a la DGII. El campo reason es opcional y se usa un motivo predeterminado si se omite.

curl -X POST {{ base_url }}/invoices/ID_DEL_DOCUMENTO/cancel \
  -H "Content-Type: application/json" \
  -H "X-API-Key: TU_API_KEY" \
  -d '{"reason": "Error en digitación de monto"}'

GET/invoices · /documents · /invoices/{id}

Lista los comprobantes emitidos (o todos los documentos con /documents) y obtiene el detalle completo de uno específico.

curl {{ base_url }}/invoices -H "X-API-Key: TU_API_KEY"
curl {{ base_url }}/invoices/ID_DEL_DOCUMENTO -H "X-API-Key: TU_API_KEY"

POST/invoices

Crea un borrador de factura o cotización (is_quotation: true) sin emitirlo. Los totales se calculan automáticamente.

Acciones posteriores

POST/invoices/{invoice_id}/payments registra un pago asociado a una factura.

POST/invoices/{invoice_id}/credit-notes crea una nota de crédito relacionada con una factura original.

Ambos endpoints requieren la API Key y devuelven un objeto JSON con success o un error. El pago debe tener un monto mayor que cero; la nota de crédito debe referenciar una factura existente.

GET/items · POST/items · PUT/items/{id}

Gestiona el catálogo de artículos y servicios (nombre, precio, código, tipo, unidad, tasa de ITBIS, stock).

GET/clients · POST/clients · GET/clients/{id}/statement

Gestiona el directorio de clientes y consulta el estado de cuenta de un cliente.

GET/dgii/rnc/{rnc}

Consulta la información fiscal de un RNC o cédula directamente en la DGII.

curl {{ base_url }}/dgii/rnc/131880681 -H "X-API-Key: TU_API_KEY"

GET/dgii/sequences

Lista las secuencias (rangos) de comprobantes fiscales autorizadas y su consumo.

GET/dgii/audit

Consulta los logs de auditoría de secuencias usadas y su estado de sincronización con la DGII.

GET/metadata/catalogs

Retorna los catálogos de referencia: unidades de medida, monedas, tipos de pago, métodos de pago, tipos de ingreso, tasas de ITBIS y tipos de comprobante e-CF.

Recepción de e-CF (DGII)

Estos endpoints son para recibir comprobantes de terceros en una instalación registrada ante la DGII. No forman parte del flujo de emisión para integradores y usan el token Bearer del flujo de autenticación DGII, no la API Key de VykOne.

GET /fe/autenticacion/api/semillaDevuelve el XML de semilla de autenticación.
POST /fe/autenticacion/api/validacioncertificadoValida el certificado y emite el token.
POST /fe/recepcion/api/ecfRecibe el XML del e-CF y responde con el ARECF firmado.
POST /fe/aprobacioncomercial/api/ecfRecibe la aprobación comercial.

Errores y estados HTTP

400Payload inválido o faltan datos requeridos.
401Falta la credencial (AUTH_REQUIRED) o es inválida (AUTH_INVALID).
403Módulo no contratado o producción no habilitada (PRODUCTION_AGREEMENT_REQUIRED).
404Factura, cliente o recurso no encontrado.
422La DGII o el proveedor rechazó la operación.
500/503Error interno o servicio externo no configurado.
